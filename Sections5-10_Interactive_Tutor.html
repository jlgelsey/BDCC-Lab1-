    Explain the formulas without jargon
    Support asks “out of all these reviews, how many mention both?” Confidence asks “among reviews mentioning queues, how many also mention price?” Lift asks “how does that conditional price share compare with the price share among all reviews?”
    A directional rule is a conditional summary, so reversing it can change confidence. It does not put events in time order and does not establish causation.
    

    

    

    Method choices and review response
    Defend the scope, not every possible method
    

    The strongest defense is knowing what the code measures and where it stops. A more advanced method is useful only when its assumptions and the resulting claim fit the project.
    

    What changed after the review?
    We tightened cost expressions, made advice filtering local, added topic-bound hotel and transport problems, exposed sentiment disagreements, and created direct target evidence. We retained class-style Apriori, recounted selected patterns across every branch, replaced the custom length-adjusted ratio with group rates, and added targeted baskets and a fixed low-rating consequent. Recommendations use descriptive percentage-point gaps with an explicit fallback to common patterns.
    Those changes improve traceability, although they do not establish human label accuracy. A pipeline that runs perfectly can still label a sentence incorrectly.
    

    Why not add Benjamini–Hochberg, logistic regression or Mantel–Haenszel?
    These were proposals in the review, not class requirements. In broad terms, Benjamini–Hochberg addresses multiple statistical tests, logistic regression models a binary outcome using predictors, and Mantel–Haenszel combines association evidence across groups. We do not use them, present their formulas or claim their benefits in this lab.
    The notebook reports descriptive patterns rather than p-values or adjusted effects, so introducing these methods would change the question and add assumptions that the current labels have not earned. “Strata” simply means groups; we show readable group counts without claiming statistical adjustment. Skipping inference means we must also skip claims that branch differences are statistically established.
    

    Why keep Apriori when there are only nine items?
    Because the task is to apply the class FIM workflow, and Apriori is correct for these review baskets. Its speed advantage is not the reason to use it at this scale. The main uncertainty is whether phrases represent real complaints, not whether another mining algorithm would count the same sets faster.
    The class functions use absolute support counts, keep a single consequent and sort deterministically. Relative support is stored separately as count divided by the relevant review population.
    

    Defend every cutoff
    1% support: requires a recurring share of the relevant review population. 30 reviews: adds a minimum count when subsets are small. 30% confidence: selects a readable conditional overlap. 1.2 lift: selects overlap above the consequent baseline. These are exploratory choices, not validated optimums or significance thresholds; support sensitivity uses 0.5%, 1% and 2%.
    ±0.05 sentiment: follows the VADER implementation's common compound thresholds. Four linking words: is a transparent local phrase heuristic. 20 detected cases: is a small-count caution and target follow-up floor. 100 group reviews: limits displayed group-rate sparsity. 50/150-word boundaries: are fixed interpretable length bands. Three leading locations: limits an otherwise large sparse display. 50 audit reviews per branch: is a feasible first audit, not a guarantee of sufficient positive examples.
    Ratings 1–2 and 4–5: separate low and favorable reviews for one descriptive contrast; the fixed-consequent extension includes all valid ratings in its baseline. One- or two-category antecedents: keeps optional low-rating rules readable. Fixed random seeds: make samples repeatable without making them independent of development by themselves.
    

    What exactly is the TF-IDF contribution?
    The shared vocabulary makes weights comparable within the corpus, while branch-average differences highlight vocabulary worth reading in context. The decision table connects terms such as hotel, staff, queues and MTR to rule choices, but it does not claim an automatic discovery of negative categories. Place names may be distinctive because they identify the branch.
    The initial rules are hypothesis-driven and the extensions are exploratory. New vocabulary should be reviewed in context, added transparently, and assessed on reviews that were not used to tune it. A larger dictionary alone does not establish better accuracy.
    

    Why does sentiment not decide basket membership?
    A positive review can contain an explicit closure, and a negative segment can mention a service without criticizing it. VADER is a lexicon-based context scorer, not a verified attraction-level classifier. We therefore use explicit problem phrases for broad baskets and show positive-context disagreements as inspection priorities.
    The optional targets require a direct phrase rather than merely sharing a segment. They are stronger evidence links, although cross-park comparisons, irony and implicit references remain unresolved. Calling the output “contextual sentiment” is necessary, not merely cautious wording.
    

    Which denominator should I say aloud?
    Main FIM and target FIM: every usable review in that branch, including empty baskets. Favorable-review support: all valid 4–5-star reviews in that branch. Low-group comparison: all valid 1–2-star reviews in that branch. Low-rating rule confidence: valid-rating reviews that contain the antecedent. Low-rating baseline: all valid-rating reviews in that branch. Context rates: all reviews in that branch and displayed group.
    Sentiment diagnostic: primary category–segment matches, not unique reviews. Aspect summaries: review-level aspect averages after averaging that review's segments. Other-branch recommendation rate: pooled reviews from every other branch, weighted implicitly by their review counts.
    

    How can I validate the labels without pretending?
    Open the exported human_review_audit.csv and ask a reader to label each category as present or absent from the full review, without showing machine predictions. Mark ambiguous cases for a second reader and agree on the category definitions before scoring. Preserve all selected rows, including reviews with no complaints.
    Compare the final human labels with the rule labels by category and branch. Count true positives, false positives and false negatives; then precision = TP/(TP+FP), and recall = TP/(TP+FN). Keep undefined scores undefined when the denominator is zero. Report the counts and sample size, and acknowledge that rare categories may require more data.
    The matched examples help diagnose errors but oversample detected cases, and the unmatched sample alone cannot measure overall recall. If the audit becomes training feedback, freeze a new version and obtain a new evaluation sample. This deliverable contains no completed human accuracy study.
    

    How do I explain “no rule” or “no target pair”?
    Say that no combination passed the declared thresholds under these phrase definitions and denominators. Sparse direct target phrases can still support case inspection, while common single categories can guide operational questions. Do not lower thresholds just to produce a longer result table or treat absence of detection as absence of a real-world problem.
    

    What remains outside this submission?
    A validated attraction-level sentiment model, a representative sample of park visitors, a tested location-similarity recommender, causal effects and current operational conditions remain outside the evidence. Reviewer location is used for descriptive coverage and group comparisons, not as a substitute for user preferences.
    Reasonable next steps are human label assessment, branch-aware attraction verification and a separately evaluated recommendation task. An external ABSA model or embedding clustering could be explored later, but model sophistication does not remove the need for evaluation.
    

    Decode unfamiliar code
    

    Regex: what do the symbols mean?
    r"..." creates a raw Python string, which keeps backslashes convenient for regular expressions. \b means a word boundary, \s+ means one or more whitespace characters, and | means “either alternative.” A question mark after a character or group makes it optional, so queues? accepts queue or queues.
    (?:...) groups a pattern without storing a separate match, while (?P<cue>...) names the matched problem expression cue. {0,4} permits zero through four repetitions. re.I ignores case. re.escape turns an attraction name into literal search text so punctuation is not accidentally treated as a pattern command.
    match.start("cue") finds where the problem word begins, which lets the code inspect words before it for denial. These conveniences make the rules explicit, but they do not give the program a full understanding of grammar.
    

    Pandas: filtering, grouping and counting
    df.loc[condition, columns] chooses matching rows and the columns to display. .eq(...), .ge(...) and .le(...) mean equals, greater than or equal, and less than or equal. & combines row conditions, and parentheses keep each condition together.
    groupby(...) collects rows sharing a key, while agg(...) specifies what to calculate in each group. size counts rows, whereas nunique counts distinct values, which is why review counts do not automatically equal evidence-row counts. reset_index() turns grouping keys back into ordinary columns.
    merge(..., validate="one_to_one") checks that each key appears once on both sides before joining. fillna replaces missing values when that replacement has a stated meaning, while np.nan preserves an undefined ratio instead of inventing zero. itertuples() reads table rows using named attributes such as row.Branch.
    

    Python sets, tuples and small functions
    A set keeps unique items, which makes it a natural review basket: five mentions of queues still become one category. A tuple stores an ordered, immutable itemset key, which can be used in a dictionary of support counts. Sorting before making a tuple gives the same key regardless of the order in which words were found.
    set_a | set_b forms their union, while issubset checks whether all requested items occur in a basket. A comprehension such as [value for value in values if condition] is a compact loop that builds a list. lambda defines a short function used once, such as testing whether a category is in a basket.
    ceil rounds the support cutoff upward: requiring at least 1% of 19,404 reviews means at least 195, not 194. assert stops execution when an expected condition fails; it is a check, not an accuracy measurement.
